Traffic quality & compliance
Business rule

Suspicion triggers investigation. Confirmed compliance risk triggers blocking.

Traffic-quality call

Do not hard-block immediately based only on suspicion.
Monitor flagged traffic and run sensitivity analysis.
If evidence confirms IVT, block/filter it.
If legitimate, keep it.
If inconclusive, continue monitoring or controlled exclusion.

Compliance call

Compliance overrides model economics.
Confirmed fraud/policy violations should be blocked regardless of model performance.
Keep the decision auditable: reason, inventory, evidence, date, action.
Re-evaluate model performance after filtering changes the traffic mix.
Trust and measurement quality come before short-term model gains11
Product requirement
User story + acceptance criteria

Route each auction to the best validated model version.

User story

As a Data Science Product Manager, I want traffic routed to the model version that performs best for validated cohorts, so we capture v2.1 efficiency gains while avoiding known regression areas.

Acceptance criteria

Routing supports campaign, device, audience, creative, and publisher segmentation.
v1.4 is enabled only for cohorts with validated ROAS / CPA improvement.
Conflicts have explicit precedence rules.
Default fallback is defined as v2.1.
Model assignment is logged for every auction.
Rollback and monitoring are defined before launch.
Routing config changes do not require full model redeployment.
